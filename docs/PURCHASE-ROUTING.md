# 收益入口复盘（0.4.2）

## 问题与规则

首页曾在缺失商家地址时突出“查看原帖找购买入口”；专题列表也直接回退原帖。这会把购买流量交给来源站。现在统一改为站内优惠详情，标注“购买入口待核实”，不猜商家或邀请码。

旧版整体替换型商家还保留原始 order_url，并提供“下单 / 注册”两个平级按钮。直接下单可能没有本站推广 Cookie，不能假定订单仍归本站。新版取消该旁路，抓取和旧快照渲染均清空 order_url，只使用 affiliate.rewrite 后的 vendor_url。

- 已配置商家：主按钮保留站长专属推广入口；支持参数模式的商家仍保留套餐路径与优惠码。
- 专属入口模式：不擅自拼接未经商家确认的深链参数，允许需要在商家站内再找套餐。
- 未配置推广但已确认官网：保留原有官网入口并清除已识别的他人推广参数，不宣称有本站佣金。
- 未确认官网：只引导站内详情，无下单按钮；可返回全部优惠与商家目录。
- 已结束、售罄、补货中：仍使用核对补货或替代套餐的文案，不承诺可下单。
- 原帖：仅在展开的“信息来源与条款核验”中提供，用于核对价格、条款和库存证据。

现有个人推广配置及环境变量覆盖机制未修改。入口参数正确不等于佣金已入账，仍取决于商家规则、Cookie、账户和订单资格；本次不涉及真实下单或后台佣金验收。

## 验证与部署

```sh
python -m pytest tests -q
python -m tools.audit_site
python -m tools.verify_live --url https://vps.869hr.uk --attempts 40 --delay 15
```

测试逐家覆盖现有推广映射和旧快照旁路清理，覆盖无 JavaScript 列表、站内详情及来源折叠。发布门禁审计首页与三个专题页；线上逐字节摘要比对首页、专题页、数据、RSS、站点地图、llms.txt 和所有优惠详情，兼容 Cloudflare 的已知分析脚本注入。

主仓库推送 main 后沿用现有 GitHub Actions → 审计 → Pages 安全直传 → 公网验收。scheduler 的复用工作流指向主仓库 main，无需复制生成器或更改每日北京时间 05:00 的调度链。
